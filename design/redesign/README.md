# Направления редизайна Disk Rescue

Дата: 2026-10-20. Статус: обсуждение, концепция ещё не выбрана.

## Кликабельные мокапы

Откройте `concepts.html` в браузере. Пять вариантов переключаются внизу;
в каждом работают локальные демонстрационные действия. Реальный сервис,
токены и файлы пользователя не используются. Интернет для мокапов не требуется.

`concepts.fragment.html` — исходный фрагмент интерактивного превью из чата.
`concepts.html` — самостоятельная версия с переключателем вариантов.

## Задача

Убрать ощущение перегруженности и разбросанного управления. Сделать понятным:
что сохраняется, куда, как идёт процесс и какое действие доступно сейчас.

Сейчас подготовка, выбор файлов, управление загрузкой и результаты находятся
на одной длинной странице. Запуск расположен у выбора папок, пауза и продолжение
у прогресса; состояние повторяется в нескольких местах. Есть отдельные кнопки
запуска для всего Диска и выбранных папок.

## Пять радикальных направлений

| Концепция | Основная модель | Компромисс |
| --- | --- | --- |
| Пошаговое спасение | Подключить → куда → что → процесс | Удобно при первом запуске; повторное использование требует короткого пути к процессу |
| Двухпанельный проводник | Папки слева, файлы справа, управление снизу | Удобно искать файлы; общую картину нужно сохранять в компактной полосе |
| Диспетчер проблем | Сохранено / в работе / нужно внимание | Удобно разбирать сбои; нельзя смешивать временную недоступность с окончательной потерей |
| Тихий прибор | Прогресс и одна основная кнопка, подробности раскрываются | Минимум нагрузки; менее удобно регулярно просматривать много файлов |
| Диалоговый помощник | Последовательные подсказки с кнопками действий | Понятная последовательность; важно не заставлять повторять разговор при каждом посещении |

Последним в карусели был открыт «Диалоговый помощник». Это не означает
окончательного выбора: пользователь попросил сохранить все варианты для обсуждения.

Ранее также обсуждались центр восстановления, отдельные разделы
«Обзор / Файлы / Настройки» и файловый менеджер с панелью загрузки.

## Следующие шаги

1. Выбрать одну концепцию или конкретное сочетание элементов из нескольких.
2. Определить главный сценарий: первый запуск, наблюдение за загрузкой,
   просмотр спасённых файлов или разбор проблем.
3. Проработать выбранный вариант для состояний: нет подключения, нет накопителя,
   неполный каталог, загрузка, остановка активных записей, пауза, ожидание повтора,
   нехватка места, обработанная очередь с недоступными оригиналами.
4. Согласовать единое место запуска/паузы/продолжения, изменение состава
   восстановления и доступ к настройкам.
5. Подготовить согласованный дизайн и план реализации, затем менять рабочий UI.

## Сохранить при реализации

- Оригиналы и превью учитываются раздельно.
- Завершение очереди не означает, что все оригиналы спасены.
- Смена назначения сохраняет старые файлы и требует явного подтверждения;
  назначения имеют собственные результаты и очереди.
- Пауза может сначала дожидаться завершения активных записей.
- Закрытие вкладки не останавливает Python-процесс.
- Выбор папок и просмотр результатов — разные действия; просмотр не меняет очередь.

## Проверка и ограничения

Синтаксис JavaScript и основные переходы проверены программно: шаги мастера,
запуск/пауза, настройки, выбор папок, результаты, переход между папками и повтор.
Визуальная проверка в браузере не выполнена: браузер автоматизации был занят.
Мокапы не реализуют реальное скачивание, проверку токена или смену назначения;
числа и предпросмотр условные. Это материал для выбора направления, не готовый UI.

Материалы сохранены без коммита. Рабочее приложение в рамках этого сохранения
не изменяется.
