# Локальный интерфейс восстановления Яндекс.Диска

## Цель и ограничения

Сохранить максимум доступных данных личного Яндекс.Диска при нестабильной работе сервиса. Объём пользователя — примерно 731 ГБ; назначение — заказанный внешний диск на 2 ТБ. До получения диска разработка и проверка выполняются на искусственных данных во временных каталогах. Реальные загрузки и авторизация не входят в проверку разработки.

Первая версия предназначена для личного использования на macOS. Публичный релиз, подтверждённая поддержка Windows и десктопное приложение — последующие этапы. Сервис может сохранить только содержимое, которое отдаёт Яндекс; недоступность файла не означает доказанную окончательную потерю.

## Согласованный состав первой версии

- Локальный веб-интерфейс и отдельный Python-процесс восстановления.
- Сохранение каталога и метаданных независимо от загрузки.
- Устойчивая очередь оригиналов и отдельная очередь превью изображений.
- Повторные попытки, пауза, продолжение после перезапуска.
- Проверка оригиналов по размеру и MD5, если облако сообщает MD5.
- Безопасное отображение облачных путей на локальные без перезаписи другого файла.
- Остановка записи при отключении выбранного тома или нехватке места.
- Понятные причины ошибок и отчёт по каждому файлу.
- Существующие команды CLI сохраняют свой интерфейс.

## Архитектура

Ядро на Python отделяется от CLI и HTTP-интерфейса. Состав: клиент Яндекс API, каталог, хранилище состояния SQLite, планировщик задач, загрузчик, контроль тома назначения и локальный HTTP-сервис. Браузер не выполняет загрузки самостоятельно. Закрытие вкладки не останавливает Python-процесс; завершение процесса останавливает работу, а последующий запуск восстанавливает очередь.

Интерфейс использует локальные HTML/CSS/JavaScript без внешних CDN. HTTP-сервис слушает только loopback. Для первой версии достаточно периодического получения состояния браузером; постоянное соединение не требуется. Конкретные зависимости и структура модулей определяются планом реализации.

SQLite, журналы и каталог размещаются в каталоге данных приложения на внутреннем диске с ограниченными правами доступа. Отсутствие внешнего диска не мешает просматривать каталог. Токен, заголовки авторизации и подписанные ссылки не сохраняются в базе или журналах.

## Подключение и локальная безопасность

Поддерживаются существующие источники токена — окружение и локальный файл — и ввод через локальный интерфейс. Введённый токен хранится в памяти процесса; после перезапуска его требуется ввести заново, если не настроен существующий локальный источник. Ответы API интерфейса никогда не возвращают токен.

Веб-сервис проверяет Host и Origin, запрещает сторонние origins, не включает CORS и защищает изменяющие запросы случайным секретом сессии. Удалённые имена файлов выводятся как текст, а не HTML. Токен отправляется только разрешённым HTTPS-хостам Яндекса; редиректы не должны обходить это ограничение.

## Каталог и состояние

Каждое сканирование получает отдельный идентификатор и статус полноты. Частично полученный каталог доступен для просмотра и восстановления, но явно обозначается незавершённым. Новое сканирование не удаляет предыдущие сведения. Файлы, отсутствующие в новом снимке, не считаются автоматически удалёнными или спасёнными.

Для записи каталога сохраняются облачный путь, доступный идентификатор ресурса, размер, MD5, тип и время наблюдения. Новое содержимое по старому пути не наследует статус проверенной копии прежнего содержимого.

Для каждого файла отдельно учитываются оригинал и превью. Состояния оригинала: ожидает, выполняется, отложен до повторной попытки, проверен по размеру и MD5, проверен только по размеру, конфликт локальной копии, требуется действие пользователя. Состояния превью: ожидает, выполняется, сохранено, превью не предоставлено, отложено. Сохранённое превью не увеличивает число восстановленных оригиналов.

После аварийного завершения незаконченные задания возвращаются в очередь. Изменения фиксируются по результатам отдельных заданий, а не только после полного прохода. CSV используется для экспорта каталога и результатов, а не как единственный источник состояния.

## Загрузка и повторные попытки

Оригиналы и превью имеют раздельные очереди с общим ограничением числа запросов. Превью можно отключить. Недоступный файл откладывается, остальные продолжаются; ошибки ограничения запросов учитывают Retry-After, если он предоставлен. Используются нарастающие задержки с разбросом и верхним пределом. Ошибки авторизации приостанавливают сетевые операции до исправления доступа; ошибки диска приостанавливают запись.

Один ресурс назначения обслуживает не более одного активного задания. Планировщик не запускает повторную запись, пока предыдущий исполнитель ещё может писать в тот же файл. Нужны ограниченные таймауты и управляемое завершение работников; схема исходника с оставленными потоками между проходами не переносится.

Пауза запрещает выдавать новые задания и останавливает текущие передачи на границах порций данных. Интерфейс подтверждает завершение активных записей, прежде чем сообщает, что диск можно отключить.

Каждая попытка пишет во временный файл в папке назначения. Итоговое имя появляется после успешной проверки и атомарного переименования. В первой версии незавершённая передача при повторе начинается сначала; частичная докачка перенесена в роадмап. Временные файлы приложения не выдаются за готовые оригиналы.

Существующий файл нельзя считать проверенным только из-за совпадения размера, если известен MD5. Несовпадающую локальную копию приложение не перезаписывает: сохраняет конфликт в состоянии и использует отдельное свободное имя для восстановленного оригинала. Для исходников без MD5 интерфейс прямо указывает, что проверен только размер.

## Пути и внешний диск

Отображение облачного пути в локальный сохраняется в базе и остаётся стабильным между запусками. Оно учитывает запрещённые символы, регистр, Unicode и совпадения после нормализации. Коллизии разрешаются устойчивым уникальным суффиксом. Запись не может выйти за выбранный каталог, включая переход через символьную ссылку. Оригиналы и превью располагаются в отдельных подкаталогах с сохранением узнаваемой структуры облака.

При выборе назначения фиксируется идентичность тома, а не только строка пути /Volumes/…. Перед началом записи и в ходе работы проверяется, что это тот же подключённый том. При исчезновении приложение приостанавливает задания и не создаёт замещающий каталог на внутреннем диске. После подключения пользователь подтверждает продолжение на распознанном томе.

Свободное место проверяется перед загрузкой и между порциями записи. Планировщик учитывает место, зарезервированное активными загрузками, и оставляет минимум 1 ГиБ свободным. Если очередной файл не помещается с этим резервом, задание не начинается; текущие ошибки заполнения диска также приводят к паузе. Проверка во время записи остаётся обязательной, поскольку место может расходоваться другими приложениями.

## Интерфейс

1. Подключение: источник токена, проверка доступа, статус подключения.
2. Каталог: начать или продолжить получение списка, полнота снимка, число файлов и объём, просмотр и фильтрация. Основное действие — восстановить весь известный каталог; выбор подмножества допустим.
3. Назначение: путь, выбранный том, свободное место и проверка готовности. Отсутствующий диск отображается как ожидаемый; загрузка заблокирована до его выбора и проверки.
4. Восстановление: старт, пауза, продолжение, отключение превью; проверенные оригиналы и сохранённые превью считаются отдельно. Отображаются переданные байты, скорость, активные задания, ожидающие повтора и причины паузы. Переданные байты не равны объёму проверенных оригиналов.
5. Результат: фильтруемый перечень файлов, путь локальной копии, уровень проверки, последняя ошибка, число попыток и экспорт CSV. Недоступные файлы остаются в перечне повторных попыток и не помечаются окончательно потерянными.

Оценка оставшегося времени при нестабильной доступности не является обязательной частью первой версии. Сравнение с локальными дисками остаётся в CLI и не блокирует спасение всего каталога.

## Проверка до получения диска

Используется тестовый источник API и временное назначение с явным тестовым режимом. Отдельный пользовательский демонстрационный продукт не создаётся. Проверяются: доступный оригинал, несовпадение MD5, совпадение размеров при разном содержимом, отсутствующее превью, временная ошибка, ограничение запросов, истёкший токен, обрыв передачи, перезапуск процесса, коллизия имён, символьная ссылка, отсутствие тома и нехватка места. Потеря тома и нехватка места моделируются без отключения реальных накопителей и без заполнения диска.

Условия готовности: исходные тесты проходят; очередь переживает перезапуск; два работника не пишут в один ресурс; оригинал не отмечается проверенным до соответствующей проверки; отсутствующий том не приводит к записи на внутренний диск; браузер показывает причины паузы и раздельные результаты оригиналов/превью; токен отсутствует в ответах и журналах. Проверка с реальным внешним диском и Яндексом выполняется отдельно после его получения.

## Роадмап

1. Докачка частей больших файлов: только при поддержке сервером диапазонов и проверке идентичности содержимого, с полной итоговой проверкой.
2. Подготовка публичного релиза: подтверждённая работа Windows, проверка на реальных файловых системах, простая установка, инструкции и сборки. Сохранение MIT и исходного copyright обязательно.
3. Десктопное приложение на общем ядре: системный выбор диска, управление фоновым процессом и хранение секретов в системном хранилище.
4. Полноценный демонстрационный режим, если он окажется полезным для знакомства с публичным приложением.

Не входят в первую версию: синхронизация с удалением, запись или удаление в облаке, стороннее облачное хранение токенов и файлов, обход прав доступа, обещание восстановления физически утраченных данных.
