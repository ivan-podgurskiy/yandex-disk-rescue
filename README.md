# yandex-disk-rescue

Спасатель файлов Яндекс.Диска, когда сайт и скачивание не работают.

*English: a small stdlib-only Python tool that uses the official Yandex.Disk REST API to (1) list your whole cloud, (2) compare it with your local drives, (3) rescue image **previews** and whatever **originals** the server still serves. See the short note at the bottom.*

## Зачем это

Когда у Яндекса сбой, обычно кажется, что всё потеряно: сайт не открывается, файлы не скачиваются. На практике это не всегда так. В нашем случае:

1. **API каталога работал**, хотя скачивание лежало. Через него можно получить полный список своих файлов: пути, размеры, контрольные суммы.
2. **Превью (уменьшенные копии) картинок отдавались заметно лучше, чем оригиналы.** В наших маленьких тестах: оригиналы отвечали примерно в 20% случаев, превью примерно в 85%. Выборки были крошечные (15 и 20 файлов), так что считайте это наблюдением, а не измерением.
3. **Оригиналы отдавались рвано**: одни файлы скачивались, другие нет, и набор менялся со временем. Помогает тактика «не зависать на мёртвом файле, взять живые, вернуться к остальным позже».

Инструмент автоматизирует всё это и заодно отвечает на вопрос «что из облака у меня уже есть на жёстких дисках, а чего нет».

> ⚠️ Честно о пределах. Это не волшебная кнопка. Он забирает то, что сервер **сейчас** отдаёт. Если файл недоступен, инструмент его не достанет. Превью это картинка в уменьшенном размере (по умолчанию примерно 200 КБ на фото), а не оригинал. У видео превью нет. Никаких гарантий.

## Что нужно

- Python 3.8+ (только стандартная библиотека, ничего ставить не надо)
- OAuth-токен **вашего** Яндекс.Диска (см. ниже)

## Токен

Токен это «ключ-карта» от вашего Диска: он даёт доступ к файлам, но не к паролю от аккаунта.

1. Получите токен для своего Диска на официальной странице Яндекса для разработчиков (поищите «Яндекс.Диск Полигон» или «OAuth-токен Яндекс.Диск»). Страница может измениться, ищите актуальный способ получить OAuth-токен для REST API Диска.
2. Сохраните его **в файл** `token.txt` рядом со скриптом (одна строка) или в переменную окружения `YADISK_TOKEN`.
3. **Не отправляйте токен никому** и не вставляйте его в чаты, issue и скриншоты. Кто его знает, тот видит ваши файлы.
4. Когда закончите, **отзовите токен** в настройках Яндекс ID (раздел про приложения и доступ к данным; названия меню у Яндекса меняются).

Подробнее: [SECURITY.md](SECURITY.md).

Клиент отправляет токен **только** на серверы `*.yandex.ru / *.yandex.net / *.yandex.com / *.yandex.by / *.yandex.kz`, и редиректы на другие хосты не выполняет. Токен нигде не печатается и автоматически не сохраняется. Токен нельзя передать аргументом командной строки.

## Локальный веб-интерфейс (новая версия)

Первая версия рассчитана на **macOS**. Python 3.8+ и стандартная библиотека, без установки пакетов и внешних CDN. Проверки разработки выполнены на macOS с Python 3.14; Python 3.8, Windows, реальные обращения к Яндекс.Диску и восстановление 731 ГБ на внешнем диске пока отдельно не проверены.

Запуск из каталога проекта:

```bash
python3 -m rescue
```

Откройте **http://127.0.0.1:8765**. Адрес доступен только на этом компьютере. Не открывайте порт наружу и не ставьте перед ним публичный прокси.

1. Введите OAuth-токен в интерфейсе либо нажмите «Из окружения / файла» для `YADISK_TOKEN`, `YADISK_TOKEN_FILE` или `token.txt`. Токен из интерфейса хранится в памяти процесса; после его перезапуска потребуется повторное подключение. Не присылайте токен в чаты.
2. Нажмите «Получить каталог». Внешний диск для этого не нужен. Неполный снимок можно продолжить; уже полученные данные сохраняются. Список повторно обходится до прохода без новых наблюдений (не более трёх проходов за попытку); если каталог продолжает меняться, он остаётся неполным и его можно продолжить. Изменения облака всё равно могут потребовать нового сканирования: каталог — набор наблюдений, а не гарантированно согласованный снимок облака в один момент.
3. Когда накопитель подключён, **создайте на нём папку** и введите абсолютный путь, например `/Volumes/MyDisk/Rescue`. Нажмите «Проверить». Отсутствующий путь приложение не создаёт вместо отключённого диска. Проверьте имя и свободное место. Перед форматированием диска сохраните нужные данные: приложение не форматирует накопители.
4. Нажмите «Начать восстановление». По умолчанию в очередь входят все известные файлы и версии, в том числе прежние наблюдения, отсутствующие в последнем каталоге. Можно выбрать подмножество последнего снимка флажками в таблице. Превью включаются перед началом новой очереди; при продолжении сохранённой очереди настройка сохраняется.
5. Для отключения накопителя нажмите «Приостановить» и дождитесь **«Активных записей нет»**, затем извлеките диск средствами macOS. Если диск пропал сам, верните тот же том и нажмите «Продолжить»; приложение проверит его идентичность.
6. Экспортируйте CSV с результатами и локальными путями. Строки, похожие на формулы, экранируются для безопасного открытия в таблицах; исходные имена остаются в базе без изменений.

### Что означает результат

- **Проверен · MD5**: размер и контрольная сумма соответствуют облачным метаданным.
- **Проверен · размер**: облако не сообщило MD5; проверен только размер, это более слабая проверка.
- **Превью сохранено**: отдельная уменьшенная копия изображения, не восстановленный оригинал.
- **Повторим**: файл пока не скачан или не прошёл проверку; причина доступна в подсказке строки и CSV. Это не доказательство окончательной потери.
- **Не предоставлено**: API не вернул превью; оригинал продолжает учитываться независимо.

Оригиналы пишутся в `originals/`, превью — в `previews/`. Имена содержат устойчивые суффиксы для защиты от коллизий и версий; исходный облачный путь и локальный путь указаны в отчёте. Существующие несовпадающие копии не перезаписываются. Файлы публикуются только после проверки. Незавершённая передача в этой версии при повторе начинается сначала, а готовые результаты очереди сохраняются.

**2 ТБ достаточно для 731 ГБ оригиналов**, если накопитель преимущественно свободен; дополнительное место требуется для превью, конфликтующих копий, новых версий и временных файлов. Приложение оставляет резерв не менее 1 ГиБ, учитывает параллельные передачи и останавливает запись при нехватке места. Проверка тома работает через macOS `diskutil`; неизвестный том не принимается. Для атомарной публикации на macOS используется переименование без перезаписи, без требования поддержки hard links. Конкретный внешний накопитель и его файловую систему нужно проверить после получения.

### Длительная работа и состояние

Закрытие вкладки **не останавливает** Python-процесс. Терминал с процессом должен оставаться открытым. Сон компьютера приостанавливает работу; процесс не предотвращает сон автоматически. Остановка — `Ctrl+C` в терминале. После перезапуска подключите токен и прежнюю папку назначения и продолжите очередь. При зависшем сетевом вызове пауза может ждать выхода работника; интерфейс не сообщает о безопасном отключении, пока остаются активные записи.

Каталог и очередь находятся в `~/Library/Application Support/YandexDiskRescue/state.sqlite`, на внутреннем диске. Ничего в облаке приложение не удаляет и не изменяет. База, отчёты и пути — личные данные. База привязана к аккаунту и назначению: для другого аккаунта или другого диска используйте отдельный каталог данных:

```bash
python3 -m rescue --data-dir /absolute/path/to/private-state --port 8767
```

Можно получать каталог до приезда накопителя, но реальную загрузку начинайте после проверки назначения. Автоматических фоновых запусков или телеметрии нет.

### Проверка без аккаунта

```bash
python3 -m unittest discover -s tests -v
python3 tests/preview_app.py
```

Второй запуск открывает тестовый сервис по `http://127.0.0.1:8766`, печатает временную папку назначения и использует только сгенерированные файлы. Введите любое тестовое значение вместо настоящего токена, задайте напечатанный путь, получите каталог и проверьте загрузку. Это тестовый стенд, не реальный Яндекс.Диск; после остановки временные данные удаляются. Не запускайте его для настоящего восстановления.

### Роадмап

- Докачка частей больших файлов при подтверждённой поддержке сервера.
- Проверенная поддержка Windows и простой публичный установщик.
- Десктопная оболочка на общем ядре, системный выбор папки и хранилище токена.
- Полноценный демонстрационный режим для публичного релиза.

## Быстрый старт

```bash
# 1. снять полный список облака (быстро, только каталог)
python yd_rescue.py list --out cloud_files.csv

# 2. описать каждый свой жёсткий диск (только чтение; подключайте по очереди)
python yd_rescue.py scan "E:\"  --label disk1
python yd_rescue.py scan "F:\"  --label disk2

# 3. что есть ТОЛЬКО в облаке (можно исключить ненужные папки)
python yd_rescue.py compare --cloud cloud_files.csv --scans scans --out only_in_cloud.csv --exclude "Загрузки"

# 4. спасти превью картинок (с сохранением структуры папок)
python yd_rescue.py previews --list only_in_cloud.csv --dest "F:\_previews"

# 5. спасти оригиналы, какие отдаются (докачивает по проходам)
python yd_rescue.py download --list only_in_cloud.csv --dest "F:\_originals"
```

Каждую команду можно прерывать и запускать заново: существующие оригиналы проверяются по размеру и MD5, если он известен. Новые команды `download` и `previews` сохраняют защищённые имена в подкаталогах `originals` и `previews` внутри `--dest`; соответствия находятся во внутреннем каталоге `~/Library/Application Support/YandexDiskRescue/cli/`. Список оставшегося сохраняется там же и копируется в назначение только при доступном прежнем томе. Незавершённое лежит в `_pending_*.csv` в папке назначения.

### Наблюдатель: отчёт каждые N минут

Пока идут `previews` и `download`, в соседнем окне терминала можно запустить:

```bash
python yd_rescue.py watch --interval 600 \
    --previews "F:\_previews"  only_in_cloud.csv \
    --originals "F:\_originals" only_in_cloud.csv
```

Каждые 10 минут он печатает, сколько файлов и гигабайт пришло за интервал, сколько всего и в процентах, сколько осталось, примерное время до конца и свободное место на диске. Если за интервал ничего не пришло, добавит `!! no progress`, а если диск отключился, напишет `destination not reachable`. Для одного отчёта используйте `--once`. Процент по превью может не дойти до 100: у некоторых картинок превью просто нет.

### Как это работает

- **compare** считает файл найденным на диске, если там есть файл **с тем же именем и точным размером** (в любой папке). Поэтому переименованные или перемещённые папки не мешают. Но если вы переименовали сам файл или пережали его, он посчитается отсутствующим: список из `compare` это **верхняя граница** того, что нужно качать.
- **previews / download** работают проходами: каждый файл пробуется быстро (таймаут `--timeout`, по умолчанию 12 с), мёртвые откладываются, и после паузы идёт следующий проход. Остановка после `--stop-after` пустых проходов подряд.
- `--workers` задаёт число потоков (по умолчанию 8). Не ставьте слишком много, это чужой сервер, которому и так плохо.
- `--size` задаёт размер превью: `S, M, L, XL, XXL, XXXL` или `ШxВ`.
- `download` проверяет размер и md5 каждого файла.
- Корзины (`$RECYCLE.BIN` и подобные) при сканировании пропускаются.

### Разложить по дискам

Скрипт не решает, какой диск что получит: это ваше дело. Подключайте нужный диск и указывайте его в `--dest`. Для разных дисков делайте отдельные списки (например, отфильтруйте `only_in_cloud.csv` как вам нужно) и запускайте `download` по очереди.

## Данные и приватность

- Скрипт общается **только** с API Яндекса. Никакой телеметрии, никаких сторонних серверов.
- Списки файлов (`*.csv`) это ваши личные данные. Они уже в `.gitignore`. Не выкладывайте их.
- Если делаете форк: проверьте перед публикацией, что в репозитории нет токена и ваших списков.

### English (short)

`yd_rescue.py` uses the official Yandex.Disk REST API with **your own** OAuth token (read from `YADISK_TOKEN` or `token.txt`, never from the command line).

`list` snapshots the cloud file list, `scan` describes a local drive, `compare` finds cloud files missing from every scanned drive (by name + exact size, so it is an upper bound), `previews` downloads reduced-size image copies, `download` fetches originals with fast-fail multi-pass retries. During the outage we observed the catalog API working, previews being served far more reliably than originals, and originals being served erratically; our samples were tiny, so treat that as an observation. No warranty; not affiliated with Yandex.
