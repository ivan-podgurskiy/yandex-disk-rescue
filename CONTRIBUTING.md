# Участие в Yandex Disk Rescue

Спасибо за помощь. Баги и предложения можно оставить в [Issues](https://github.com/ivan-podgurskiy/yandex-disk-rescue/issues/new/choose). Для небольших исправлений присылайте pull request; крупные изменения лучше сначала обсудить в issue.

## Локальная проверка

Целевая среда — macOS. Для Python-кода внешние зависимости не нужны.

```bash
python3 -m unittest discover -s tests -v
node --check rescue/web/app.js
python3 tests/preview_app.py
```

Последняя команда запускает стенд с искусственными данными на http://127.0.0.1:8766. Используйте тестовый токен и напечатанный временный путь, а не настоящий аккаунт.

Сценарии `tests/setup_ui.cjs` и `tests/recovery_ui.cjs` требуют установленного Playwright и Google Chrome. Они запускаются отдельно через Node; если Playwright установлен вне проекта, укажите каталог модулей через `NODE_PATH`.

## Изменения

- Делайте изменения небольшими и описывайте проблему, результат и выполненные проверки в PR.
- Для изменений логики добавляйте проверку поведения. Для документации проверьте команды, ссылки и соответствие текущему коду.
- Работа с файлами должна сохранять защиту от перезаписи, проверку назначения и безопасную паузу.
- Не добавляйте токены, подписанные URL, SQLite-базы, личные CSV и реальные имена файлов. Для тестов используйте искусственные данные.
- Не вызывайте реальный API в автоматических тестах.

## Структура

| Путь | Содержимое |
| --- | --- |
| `rescue/` | API-клиент, каталог SQLite, очередь, запись файлов и локальный HTTP-сервис |
| `rescue/web/` | Интерфейс без сборки и внешних CDN |
| `yd_rescue.py` | Команды CLI |
| `tests/` | Автотесты, искусственный API и демонстрационный стенд |
| `docs/guide.md` | Руководство пользователя |

Ограничения и модель защиты описаны в [SECURITY.md](SECURITY.md). Код распространяется по [MIT](LICENSE).
